# Penpot Localization project context

## Purpose and document ownership

Build a free, open-source plugin for design.penpot.app that switches tagged design text with one language dropdown. It remains an unreleased prototype. The [testing record](TESTING.md#validation-record) holds validation evidence; the [release plan](V0_1_0_PLAN.md) holds outstanding work.

## Product decisions

- Translation keys identify text independently of its displayed value. The [README contract](../README.md#translation-json) defines the language-first flat maps, matching rules, and exact input limits.
- Translations come exclusively from explicit local imports or their saved copies. The bundled dictionary and automatic fallback were removed on 2026-11-15. Since 2026-11-16, JSON contents, filename, and selected language persist in Penpot's plugin-local browser storage, separately by design-file ID. They are not embedded in the design, shared across a project folder, or synchronized with collaborators/devices. No backend, translation service, API key, upload, or telemetry is part of the product.
- Changing language applies immediately. Successful explicit imports/reimports automatically apply only when the previously selected language exists in the new dictionary; otherwise the selection is cleared. A prominent, always-visible apply button supports saved selections, scope changes, retries, and newly added tagged text without reimporting or switching languages. It is disabled while busy or without a valid selection. Startup restores choices without applying; scope changes, forgetting, rejected imports, and canceled picks must not mutate design text. Invalid imports retain the previous dictionary and selection. Scope covers the current page or current file, never other files, and is not persisted.
- The release scope is literal string replacement plus recognized-language RTL text direction and reversible layout mirroring. RTL detection uses documented built-in base/script codes without changing the JSON contract. Text direction/alignment follows automatic language changes, but layout mirroring never does: automatic language/reimport application preserves the current layout state. The session-only checkbox reflects confirmed durable mirrored layout in the selected scope and is submitted only by manual Apply; it is not a saved preference and its checked target is independent of the selected language. Supported layout changes are horizontal positions/constraints, asymmetric padding/margins, and flex direction/alignment. Grid/component layout, directional artwork, font substitution, and arbitrary repair remain outside v0.1.0, as do interpolation, pluralization, and machine translation.
- Prefer plain JavaScript, HTML, JSON, and standard-library tooling. Extract small pure planning/validation functions with a Penpot adapter as complexity grows; dependencies require a demonstrated need.

## Current architecture

| Surface | Responsibility |
| --- | --- |
| `manifest.json` | Manifest schema version 2, relative runtime entry, content permissions, and `allow:localstorage`. The schema version is separate from the plugin release number. |
| `plugin.js` | Sole Penpot API adapter: opens the UI; validates saved-import, recovery-status, and mutation requests; plans text/style/layout apply and restore operations; groups writes in Penpot history; maintains session text recovery and durable text-free RTL shape metadata; and returns plain-data partial results. |
| `index.html` | Controls, local `File.arrayBuffer()` import with strict UTF-8 decoding, whole-dictionary validation, saved-copy/language preselection, automatic language/reimport text application without layout mutation, confirmed mirrored-state display/manual Apply control, persistent apply/restore actions, correlated plain-data messages, and text-based status rendering. |
| `server.py` | Development-only serving from the script directory on `127.0.0.1:4400`; explicit runtime-asset allowlist, symlink refusal, CORS, and no directory listings. |

The UI bounds file size and total dictionary contents before replacing the active import. Imports check the raw byte count and decode with a fatal UTF-8 decoder before accepting or saving content; malformed sequences leave the active and saved imports unchanged. An initial BOM is preserved in the saved text and tolerated during JSON parsing. Before `File.arrayBuffer()`, the UI requests a correlated file/page identity snapshot from the adapter. A retained-language automatic apply carries that page ID; page scope rejects a changed active page, while file scope remains valid because navigation does not change its target. The plugin independently validates the complete dictionary envelope, selected language/map, scope, design-file identity, optional captured page identity, and own-property membership before planning design writes. Context, apply, and restore messages use positive numeric request IDs. The UI accepts results only from its parent for the matching pending request, validates all result fields, and releases controls in `finally`, including malformed replies and failures. Apply/Restore results retain aggregate counts and split layout subtree skips from unsupported targets, unreadable metadata from external conflicts, and managed property failures from other failures; layout failures carry a fixed-key count map rather than shape IDs, values, or raw host exceptions. Foreign, stale, duplicate, and out-of-order replies do not affect status or busy state. Failed sends also restore controls. These checks do not make mutations atomic.

Saved imports use versioned records (`version`, `name`, raw JSON `text`, `language`) under `localization.saved-import.v1:<fileId>`. The RTL layout checkbox is not persisted; legacy `localization.rtl-layout.v1:<fileId>` values are ignored. Storage requests/results carry actions and numeric request IDs; the UI ignores stale/foreign replies. Startup and forgetting lock controls until a matching reply or a synchronous send failure, with loading state restored in `finally`; recovery-status checks are non-blocking. Failed storage sends clear pending state and show generic errors; failed saves do not prevent automatic application. Restored copies are labeled and never populate the native file input or reread the original file. Storage and mutation requests reject changed file identities; reopening is required after switching design files.

Recognized RTL languages set uniform tagged text to `rtl`, swap physical left/right alignment, and retain center/justify. LTR application restores each managed text layer's baseline. Managed layout mirroring keeps top-level boards fixed, traverses supported plain/flex descendants, reflects plain/absolute positions, swaps horizontal constraints and asymmetric spacing, reverses row flex direction, and swaps horizontal start/end alignment for column flex. Grid and component layout subtrees are counted and skipped; unavailable/invalid host values are omitted before planning, and one rejected property does not block supported properties on the same shape. Artwork is never flipped. Each affected shape stores only versioned baseline, last-written, confirmed/pending state, and style or layout values under plugin data—never imported or prior text. Pending metadata is written before its corresponding property setters and finalized after exact readback, so metadata failure prevents untracked style/layout writes and partial setter failures remain safely retryable. A pending layout transition makes the reported mirrored state incomplete and cannot overwrite the checkbox's current manual target as though it were confirmed. Invalid or unreadable durable metadata is treated as a conflict/failure without blocking eligible text replacement or flooding recovery scans; it is not overwritten because its baseline cannot be proven. Baseline-state divergence can be adopted on a future RTL apply; confirmed active-RTL divergence is a conflict and receives no style/layout write.

File reads are serialized. The UI allows one context capture, apply, or restore request at a time and disables import, picker, language, scope, forget, reapply, and restore controls until its matching result. A successful import starts automatic application after reading/validation finishes and its read lock is released; storage saving is independent of apply success. Scope defaults to the current page on every launch, including when a saved import is restored. File/page identities and scope are captured before asynchronous reads or adapter traversal and rechecked before writes. Matching trims the key after the exact `i18n.` prefix and is case sensitive. Already-correct values avoid a setter call. Before a changed whole-text write, the adapter inspects every documented mixed-capable aggregate style property; mixed-style layers are skipped without mutation and the UI explains the count. Inspection failures receive no write. The adapter completes traversal and builds a plain-data operation plan before mutation. Traversal failures are counted per page without hiding safe-page results; setter, conflict, history, missing-target, and restore outcomes remain explicit. Successful setters are read back before they are counted. Console diagnostics are generic and exclude imported keys, design text, and raw host exceptions. Setter/readback behavior, uniform-style preservation, and mixed-style detection can be checked in a specific Penpot environment when relevant.

**Source** is the visible filename display, including a saved-copy marker after reopening. A labeled native button opens a hidden native file input; this avoids the browser's empty “no file chosen” display contradicting the active saved copy. Opening the picker clears only the input selection so the same file can be reimported. Cancellation and rejected replacements retain the active dictionary, source, and saved copy.

The apply action remains visible after successful updates and uses **Apply to current page** / **Apply to all pages** to identify the selected scope. It is disabled without a selected language/dictionary/file or while busy; an in-flight apply shows **Applying…**. Transport, malformed-result, unexpected operation, page-inspection, text-race, and history failures use red error styling and show **Try again** for the failed language/scope/dictionary. Expected partial outcomes—missing keys, mixed styles, unsupported/component/grid layout targets, managed RTL property rejections, unreadable metadata, and external style/layout conflicts—use warning styling and retain the normal Apply label because an identical retry is not expected to resolve them. The restore action uses the same scope selector and becomes available after a successful plugin write. It reports conflicts, missing targets, mixed styles, setter failures, and history failures without overwriting divergent text. Forgetting saved import data does not clear the independent session recovery journal. Focused apply/restore buttons regain focus after their operation. There is no last-success visibility tracking: users can explicitly reapply to newly added text, external edits, or the current page without toggling language or reimporting.

## Planned mutation and recovery design

The code implements this contract with automated regression coverage, and functional localization plus repeated language switching followed by Restore have been reported working in Penpot. Detailed history, cross-page, setter-readback, and layout/style observations remain optional compatibility checks rather than release gates. Priorities and progress belong in the release plan.

- **Plan before writes:** validate the complete request, capture file/page identities and intended scope, and build an operation plan before opening history or calling setters. Automatic reimports capture context before asynchronous file reads. Apply and restore share the current-page default, one-pending-operation lock, response correlation/validation, and context recheck.
- **Preserve and report:** change only matching text in scope, including repeated keys. RTL direction/alignment is part of matching-text application; layout mutation requires the explicit option. Preserve grow settings and unsupported properties; detect and skip mixed-style text, grid/component layout, metadata failures, and conflicts with explanations. Report text, style, layout, skip, failure, missing-target, traversal, and history outcomes without concealing successful writes. Exact readback gates successful counts; environment-specific layout fidelity can be checked when relevant.
- **Group undo:** each mutating apply/restore opens one history block after planning and closes it in `finally`, including setter failures. A history-start failure prevents writes; a history-finish failure preserves and reports partial results. Non-mutating requests do not add empty blocks. Grouping is not rollback or durable backup. Cross-page undo/redo is available as an optional compatibility check.
- **Restore without overwriting edits:** the session journal remains text-only and keyed by file/page/shape ID. Durable shape plugin data adds text-free RTL style/layout baselines and active state. Repeated text writes preserve the first uninterrupted original; baseline RTL metadata supports idempotent reapply and reopening. Restore writes only from last plugin-written values, returns eligible text/style/layout values in one history block, and retains conflicts/failures for retry. Missing targets, external edits, and undo/redo divergence are reported without writes; Restore never deletes or recreates layers. Closing clears only text recovery.

Layout, fonts, components, locked layers, and recovery edge cases can be investigated with the optional compatibility checks when relevant. The project does not claim a broad Penpot/browser version range.
