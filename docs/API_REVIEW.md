# Penpot Plugin API review

Initial documentation review 2026-11-14; file identity, storage, manifest, messaging, and text-style sources rechecked 2026-11-16; page identity/lookup, history, text direction, plugin data, geometry, flex, and layout-child sources rechecked 2026-11-17; text, plugin-data, flex, and layout-child contracts rechecked 2026-11-18 for the RTL host-compatibility fix; the optional `Page.findShapes` criteria contract was rechecked 2026-11-19 while investigating baseline layout recovery. This records documented contracts and API assumptions; runtime evidence belongs in [the testing record](TESTING.md#validation-record). Recheck the relevant official sources when changing these integrations.

| Surface | Documented contract and integration note |
| --- | --- |
| Manifest | Relative runtime assets require numeric schema `version: 2`; this is separate from a plugin release version. |
| `penpot.ui.open(name, url, options)` | URL string and optional dimensions. The plugin explicitly loads `index.html`; the guide's empty-URL example was not itself a proven bug. Hosted subpath loading can be checked during release packaging. |
| `ui.onMessage`, `ui.sendMessage` | Callbacks receive messages directly; retain plain payloads rather than another ecosystem's envelope. Rechecked 2026-11-17 for pre-read context capture: context, apply, and restore use plugin-defined positive numeric request IDs, echoed on every response. The UI correlates and validates results and locks conflicting actions while one context/mutation request is pending. These protocols add no host API or permission. |
| UI `parent.postMessage` | Official examples use a plain payload and `"*"`. Validate parent source on replies. Narrow the target origin only after establishing the actual embedding origin, which need not equal the static asset origin. Rechecked 2026-11-17 for context capture: synchronous send failures are handled locally, while foreign/stale/malformed context replies cannot release the read lock or start file reading. Recovery status uses its layout completeness flag to expose a retry. Apply and switch replies report layers skipped because their unset direction cannot be restored. Permissions are unchanged. |
| Page direction and navigation | Rechecked 2026-11-26. `Page` exposes no direction attribute. The adapter stages the source and requested directions in page plugin data and verifies readback before shape conversion. It confirms `ltr`/`rtl` after managed writes, and Restore sets `auto` per successfully recovered page. The documented `pagechange`, `filechange`, and `contentsave` events require the existing `content:read` permission and trigger a plain UI invalidation. The status reply contains the current page ID and scope direction; the UI echoes that page ID on a page-scoped direction request. Real-host event delivery, page plugin-data persistence, and undo together with shape writes remain compatibility checks. |
| Browser file import | `File` inherits `Blob.arrayBuffer()` for raw bytes. Check their length before decoding with `TextDecoder("utf-8", { fatal: true, ignoreBOM: true })`; malformed input throws instead of substituting characters. Preserve the initial BOM in saved text and strip it only for parsing. These are browser APIs used in the UI, not Penpot adapter APIs. |
| `currentPage`, `currentFile` | Nullable proxies; guard absence of an open page/file. Before a local file read, the adapter returns validated file/page IDs as plain data. Page-scoped automatic apply rejects a different current page; file-scoped apply accepts active-page navigation because its target remains every page. Rechecked 2026-11-17 against the Penpot and Page interfaces. |
| `File.id` | Read-only unique design-file identifier. The documented File interface has no project-folder ID. Saved copies are keyed by this ID; save/forget/apply reject a different current-file ID. |
| `penpot.localStorage` | Plugin-owned browser storage; `getItem(key): string`, `setItem(key, value): void`, `removeItem(key): void`, requiring `allow:localstorage`. Store an explicit JSON string; validate parsed records on load and before saving. Treat null/undefined/empty reads as missing, catch permission/quota/storage errors without exposing their contents, and do not assume synchronization or indefinite retention. Real-host persistence and missing-key behavior remain to be observed. |
| `File.pages` | Array of Page proxies. Penpot 2.19.3 rejects text direction, alignment, geometry, and shape plugin-data writes on inactive pages. File-wide mutations await `penpot.openPage(pageId)` with the existing `content:read` permission and recheck the captured file and active page before each group of writes. Page plugin-data setters have no equivalent active-page guard, so the adapter verifies activation before writing them too. |
| `Page.id`, `findShapes`, `getShapeById` | `id` is the page's unique string identifier; `findShapes({type: 'text'})` returns matching Shape proxies; criteria are optional, so `findShapes()` is the documented all-shapes scan used for durable recovery metadata; `getShapeById(id)` returns a shape or `null`. Apply planning captures plain page/shape IDs, and execution/restore resolves targets through the captured page. Confirm descendants, components, lookup after a layer is deleted outside the plugin, and non-active-page lookup in Penpot. |
| `Text.characters` and style properties | `characters` is a writable whole-text string. Aggregate font, spacing, transform, decoration, direction, alignment, and fill properties document `"mixed"` when multiple values apply. Before a changed whole-text write, the plugin checks every documented mixed-capable property and skips the layer if any is mixed. `TextRange.characters` is read-only, so the current flat translation contract cannot safely map replacement content to style ranges. Real-host detection and uniform-style preservation remain manual checks. |
| RTL text style | `Text.direction` documents `"ltr"`, `"rtl"`, `"mixed"`, or `null`; `Text.align` documents physical `"left"`, `"right"`, `"center"`, `"justify"`, `"mixed"`, or `null`. There are no logical `start`/`end` text-alignment values. The adapter sets either explicit direction, adjusts physical alignment when switching direction, preserves center/justify, records uniform baselines, and skips mixed direction/alignment. The 2.19.3 direction and alignment setters require strings. A layer with an unset direction can still be translated, but its direction style is skipped so it stays recoverable. Writable behavior and readback remain real-host compatibility checks. |
| Shape plugin data | `getPluginData(key)` and `setPluginData(key, value)` store plugin-owned strings on Page and Shape APIs. RTL records use a private versioned key and contain only style/layout values plus baseline, last-written, and confirmed/pending state—never imported or prior text. Both the pending and confirmed records require readback. A silent pending-record rejection blocks property setters, and a silent confirmation failure leaves the state pending for recovery. Rechecked 2026-11-18: both methods remain documented on shape interfaces and return a string/void respectively. Invalid or unreadable records cannot prove a baseline, so the adapter reports/skips them instead of overwriting them or blocking text replacement. The API documents no delete method, so baseline-state records may remain on shapes for safe future rebasing. Persistence, collaboration visibility, history interaction, and size behavior need real-host observation. |
| Shape geometry and constraints | Shape `x` and `constraintsHorizontal` are writable; `width`, `parent`, and `parentX` are read-only. Mirroring records parent-relative offsets and writes the absolute target through `Shape.x`, using the parent’s position after its own move. It continues to read historical absolute position records, swaps only left/right constraints, keeps top-level boards fixed, and re-resolves shapes before writes. Layout settling and nested coordinate behavior remain real-host checks. |
| Board flex/grid layout | `Board.flex` and `Board.grid` are read-only references to writable layout objects. Flex `dir` supports row reversals; common layout exposes left/right padding and start/end alignment. Rechecked 2026-11-18: `alignItems` is optional even though direction and padding are documented as required. The adapter therefore plans only present, validated values, requires nonnegative padding, and isolates setter/readback failures per property. Grid direction does not provide a horizontal reverse value and grid tracks/cells require structural operations, so grid-managed subtrees are skipped. Component-managed subtrees are also skipped to avoid implicit overrides. |
| Layout child properties | `layoutChild` is a read-only reference whose documented fields include `absolute`, `alignSelf`, and side-specific margins. Rechecked 2026-11-18: side margins are numbers and `alignSelf` has the documented start/end/center/auto/stretch values. The adapter writes only validated left/right margins and horizontal start/end alignment, and reflects `x` only for plain-layout children or flex children marked absolute. Real-host setter behavior remains to be checked. |
| `Text.growType` | `fixed`, `auto-width`, or `auto-height`; leaving it untouched does not prevent layout reflow. |
| History | Rechecked 2026-11-17: `undoBlockBegin(): Symbol` starts a block whose operations should undo together; `undoBlockFinish(blockId)` ends that exact block. No rollback method is documented. The adapter opens and closes a block around each active page’s writes. Penpot 2.19.3 uses a workspace-wide transaction with a timeout, so navigation runs outside history blocks. A start failure blocks writes for that page, and finish failures are reported with partial results. Undo/redo after file-wide operations remains a live compatibility check. |
| Permissions | Content write includes read. Explicit content read/write plus `allow:localstorage` support design updates and saved imports; no user/library/network-service permissions are needed. Existing installations need the updated manifest permissions. |
